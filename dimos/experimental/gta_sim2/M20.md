# M20 in the GTA/Sim2 experiment

This is on `pim/feat/experimental-gta-sim2-g1`, based on Pim's Sim2 messages,
USD/HardwareModule composition, physics and sensor stack. It does not use the
older M20 simulation as its dynamics engine. G1 remains a separate session.

## Measured speed envelope (November 26)

The browser service opts into `--max-forward-speed 3`; the reusable policy's
default remains 1.5 m/s. Browser gears are expressed in m/s and normalized against
the running session's advertised limit. The viewer shows measured ground speed
separately. Sideways and yaw limits, motor torques, actor scales, 500 Hz physics
and 50 Hz inference are unchanged. This is not simulation time acceleration.

The ArenaX deployment config at the pinned revision below exposes a 2 m/s command
limit; it does not establish a higher-speed training envelope. Separate Sim2 runs
with the same checkpoint/model measured:

| Trial | Result |
|---|---|
| 3 m/s forward on flat ground | 2.95 m/s median after ramp-up; about 3.01 m travelled after release; remained upright |
| 3 m/s on streamed street | 2.95 m/s median while commanded; 28 exact-state handoffs, zero rejections/state/acceleration discontinuities; 1.00× real time |
| 3 m/s command with eight-second collision preparation and reversal | Governor slowed travel; four handoffs; stayed 0.34 m inside the braking boundary, with a further 2 m before the hard resident boundary |
| Forward to reverse at ±3 m/s on flat ground | Stayed upright; about 3.08 m braking travel after final release |
| Unrestricted 3 m/s plus 0.7 rad/s yaw | Stayed upright but barely turned; unsuitable for browser steering |

| Unrestricted 4 and 5 m/s on flat ground | Overshot requested speeds and fell; these settings are not exposed in the viewer |

When yaw input exceeds 0.1 rad/s, the browser policy limits forward/reverse travel
to 1.5 m/s, using the existing acceleration ramp. Releasing steering allows the
selected straight-line speed again. The collision governor can further reduce
travel; the viewer distinguishes turning reduction from coverage reduction.
Use the lower gears for stairs and tight spaces. These trials establish a useful
experimental envelope, not reliable tracking over all terrain: at 3 m/s the
street run drifted off heading and slowed against scenery. The existing collision
window and cache budgets were sufficient; they were not enlarged for this change.

Reproduce the brake/turn tests with `demo_m20_eval --speed 3 --seconds 22

plus the existing scene/policy/profile/output/terrain arguments. Omitting

## Global collision streaming (November 26)

The M20 browser session now uses `WorldStreamingMujocoBackend` and the
`world-m20/catalog/catalog.json` catalog, replacing the fixed 80 m NPZ limit.
The legacy NPZ backend remains available for comparison. This is world-scale
residency with a fixed contact-resolution window; global indexed extent is not
a certification that every place in the map has complete physics.

### Placement and dependency identity

SixNG's `worlddeps` reads metadata continuation pages and the declared map root.
The world census is now 23,535 maps / 1,670,442 entities, matching Leonida's
census. All 214,702 authored parent links resolve, with zero ambiguous targets.
Identity is `(map resource, original entity-reference ordinal)`, including slots
occupied by unknown classes. Repeated references cannot silently acquire another
entity's ordinal. Parent-map selectors use the authored parent array. A full
second export checked the declared root against the previously selected first
map block: zero differences in this dataset. The regression fixture covers a
declared root that is not the first map block.

The index contains 1,549,300 HD/orphan entity placements, 85,306 world-bound
resources and 478 interior instances with exact collider links. Model lookup
checks both the 32-bit name hash and 64-bit archetype key. Duplicate model keys
are withheld by the builder; the 24 duplicated keys in this archive occur in
zero placed entities. Local interior/group resources are not treated as world
coordinates. Heuristic interior associations, missing model/archetype links and
unclassified origin-local bounds remain explicit coverage gaps. Physics-dictionary
references are preserved as dependencies; unresolved dictionary-only collision
is not invented from the drawable's AABB.

### Residency, preparation and handoff

SQLite R-trees fetch intersecting placed bounds. The physics window is a 24 m
cube on an 8 m grid. Whole selected triangles become the existing 4 cm backed
prisms; analytic spheres/capsules/cylinders remain native shapes and boxes remain
convex boxes. There is no distance-driven decimation of loaded contact surfaces.
Source child collision masks exclude weapon-only and ped-only helpers; this
replaces the old filename-specific exclusion of the overlapping low-detail floor.
Material friction is still an explicit uniform 0.8 assumption.

Limits are 256 MiB of accounted decoded geometry, 2 GiB of cooked source files,
and eight compiled MJB windows / 512 MiB on disk. These are cache budgets, not a
total process RSS limit. A window admits at most 10,000 source instances, 50,000 shapes and 64 explicit
dynamic objects. The cooked cache has interprocess locking. Catalog database,
decoder and source-index digests are recorded; archive size/mtime changes reject
the catalog. Generated assets, binaries and world databases remain outside Git.

An owned CPU compiler process decodes/cooks upcoming windows. Route projections
or measured velocity choose the next center using travel during loading plus
braking distance and a 0.5 s margin, bounded by the protected window. Measured p95 load latency and the
age of an outstanding load feed the policy's stopping envelope
`v*T + v*v/(2*0.75) <= remaining distance`. The boundary governor lives in the
M20 policy, so browser and scripted commands share it. It uses timestamped world
observations and stops commanding travel if those observations become stale.
It begins limiting speed 3 m inside the resident edge; the hard fault has another
2 m reserve. The 0.75 m/s² braking allowance is an experimental assumption,
validated on this road and policy, not a guarantee on arbitrary slopes/surfaces.

Route hints use the existing world-scoped CBOR action extension, key `gta/route`,
with `points` (1–256 local XYZ waypoints) and `expires_at_s` (within five simulation
seconds). Hints affect prefetch only. Loaded contacts must retain identical named
geometry and material/solver parameters before a swap is accepted. Shared named
coordinates, warmstarts, controls, forces, gains, activations and time transfer;
robot body/joint identities remain unchanged. Loading and model retirement run
outside the physics owner. Failed preparation leaves the current window active
and the policy governed; crossing the hard resident limit stops the simulation.

### Persistent objects

The catalog builder accepts `--objects reviewed-objects.json`, keyed by stable
placement identity. Definitions require `kind` (`free` or `hinge`), `provenance`,
mass and principal inertia, with optional `inertia_quaternion_wxyz`. Optional center of mass and pivot are in asset-local
metres. Hinges additionally require local `axis` and `range` in radians, with
optional `home` and `damping`. Definitions must refer to complete supported
colliders; unsupported fragments cannot become dynamic via a bounding-box proxy.

Whole awake bodies and their contact-connected islands stay resident, with
nearby support geometry. Only objects quiet for one simulation second and not
touching a retained awake body may unload. Their positions, orientations, joint
coordinates, velocities and warmstarts are persisted through a bounded writer
queue into a catalog-bound SQLite WAL database. A second R-tree locates moved
objects at their current positions. A returning actor restores the latest state,
including when its geometry came from an MJB cache. Loaded objects publish the
`gta/objects` world CBOR extension.

The live GTA catalog currently has no automatic dynamic-object declarations.
The separate door evaluation catalog described below derives intact single-hinge
assemblies; contact-clearance failures prevent enabling it globally. Free-body
and awake/contact rules retain explicit-fixture coverage. SixNG consumes
`gta/objects` for both observer and sensor
renders. The physics pivot, scale and orientation are converted to the GLB's
coordinate system; the corresponding static placement is suppressed. Matching
requires a unique source map, model and original position (within 1 cm), because
the legacy render bake does not carry authored ordinals. Ambiguous or absent
matches fail explicitly. A packet may contain at most 4,096 visual overrides.

Persistent snapshots also retain visual source metadata. A separate R-tree indexes
the original locations, so a moved object cannot reappear at its spawn when the
camera returns there. Optical queries include both original and current locations
within 750 m, cached for at most 250 ms (or 10 m camera movement); current physics
observations override disk snapshots. This is the HD-object rendering range, not
a claim that distant aggregate LOD meshes have been made destructible. Persistent
state infrastructure does not imply all GTA props are already interactive.

## Integration

`prepare_m20` replaces only the robot in a copy of the authored street patch.
Native MJCF goes through MuJoCo's USD importer, with explicit repair of visual
collision flags and material bindings. An audit compares collision counts,
primitive sizes/transforms, friction, contact solver parameters, mass/inertia,
joint dynamics and motor limits to native MJCF. HardwareModule mounts contribute an IMU and
camera. Encoders and ideal attitude observations are acquired on the simulation
clock, joined by acquisition time and consumed once per 20 ms boundary.

The actor publishes the current Sim2 atomic five-interface `ActionCommand`:
position, velocity, kp, kd and effort, with clock ID, sequence and 100 ms expiry.
Leg joints have position targets; wheels have velocity targets with zero kp.
Body commands are slew-limited on the simulation clock (forward 2 m/s²,
lateral 1 m/s², yaw 2 rad/s²). Release and command expiry decelerate through
the actor before parking; abruptly locking wheels at 1.5 m/s pitched the robot
down in the initial browser trial. The parking stance holds home leg angles;
wheels hold their measured angles at the stop transition (kp 20, kd 2), and
actor history resets. This reduces the public actor's observed zero-command
creep; it is not a world-position lock. Movement selects the actor again with its original gains. Out-of-range
actor position targets are bounded for the message contract, with the equivalent
PD torque retained as feedforward effort.

Motor limits remain 76.4 Nm for legs and 21.6 Nm for SDK wheels (20 Nm for
DreamWaQ wheels). No force multiplier, root-velocity override or teleport drives
locomotion. The blueprint rejects a scene with the wrong home pose/gains.

The SixNG observer renders measured articulated body poses independently of
physics. Sim2's camera uses its own acquisition contract. The browser image is
an observer stream, not a fabricated Sim2 camera publication. No lidar is mounted
in this first M20 configuration.

The compiler is an explicitly owned subprocess because DimOS workers are Python
multiprocessing daemons. It reads the same composed USD, prepares collision-only
models, and sends compiled MJB files through a private temporary directory. It is
terminated and reaped on shutdown. Python mesh construction does not share the
physics thread's GIL. The existing Sim2 owner still advances all physical time.

At adoption, the backend verifies dynamic IDs/order, masses, inertias, coordinate
addresses and actuator transmissions, retains active contact colliders, and
copies `mjSTATE_INTEGRATION` plus Sim2's mutable actuator gains and biases. The
transfer is checked for exact equality. Pose, velocity, actuation, external forces,
solver warm start, time and controller history are not reset. Contact surfaces
within 2 m of the robot must remain present. The acceleration diagnostic evaluates
both models with the same current controls; comparing against the previous step's
cached acceleration would incorrectly attribute a new motor command to streaming.

Whole source triangles have stable IDs and remain geometrically identical across
windows. There are no artificial tile-edge cuts, duplicate colliders in overlap,
or heightfields that fill holes. The collider is a 4 cm triangular prism, as in
the baseline. Streaming changes only world-attached geoms, so body/joint schemas
and sensor scene revisions remain unchanged. The catalog digest participates in
the composed USD identity and is checked before physics starts. Optical proxy
geometry currently stays resident; SixNG separately streams its detailed imagery.

The backend stops the simulation before leaving its protected resident area if
prefetch fails. It also stops at the indexed coverage boundary. The browser's
outward-command clamp currently shares the backend's 2 m coverage threshold;
it does not provide an earlier braking margin. A user's drive reached this
threshold with remaining momentum and faulted after seven successful window
changes. Anticipatory braking remains necessary. This is an explicit fault,
not an invented floor or a teleport.
Only one floating robot is supported by this first backend.

## From residency to physics LOD

The next stages should keep three different decisions separate:

1. **Collision residency:** page exact nearby static geometry from a spatial index,
   with stable source IDs, a bounded compiled-window cache, prefetch based on speed
   and route, and a protected contact region. Expand coverage only after auditing
   overlapping LOD bounds, missing placements and gaps against rendered geometry.
   A larger index alone does not establish physical coverage.
2. **Collision detail:** use simplified far collision only for objects that cannot
   enter the robot's contact/reachable region before refinement completes. Stairs,
   thin rails, holes, door gaps and manipulation surfaces require explicit geometric
   error limits. Never swap a coarse surface beneath a loaded wheel or foot. Switch
   outside contact, with hysteresis and velocity-dependent reach/braking margins.
3. **Dynamic activity and persistent state:** preserve each door/prop's stable ID,
   pose, velocity, joint state, material and sleep state independently of its render
   tile. Awake interacting bodies form one contact island and stay at the robot's
   physics rate. Far bodies can sleep only when physically settled; a thrown object
   or moving door cannot be frozen merely because the camera moved away. Reentering
   a region restores the changed world, not the game's initial asset placement.

Multiple robots require the union of their protected regions and contact islands.
Overlapping islands must share one physical authority; independently simulating the
same door in two windows gives contradictory state. Sensor geometry/detail is a
separate policy from collision detail: a distant object can still matter to a
camera or lidar while requiring no dynamics updates. Sim2 clocks and USD identity
remain the boundary between these systems.

Before calling this seamless, require forward/reverse routes and revisits across
many seams, loaded-contact comparisons against a fully resident reference, bounded
position/velocity/force error, no target expirations induced by compilation, deadline
measurements including model retirement and IPC, fault injection for missing/slow
assets, and persistent door/object round trips. The current sphere regression checks
that evicting distant geometry gives the same next step while a contact is loaded;
it also rejects unloading that collider or changing the robot mass.

MuJoCo supports [model editing](https://mujoco.readthedocs.io/en/stable/programming/modeledit.html)
and exposes the [integration state](https://mujoco.readthedocs.io/en/stable/programming/simulation.html#state-and-control).
The experimental two-model handoff uses those public primitives, with additional
checks for the current Sim2 contract.

### Findings that change the implementation

- Leonida's [world format notes](https://github.com/ubiquitarianism/leonida/blob/a73a57e1339be072baf5522351c8ec7f1482b56b/docs/world.md)
  identify an authored parent-map array (`75d16adf`) and signed per-entity
  selector (`84799847`). `parentIndex` addresses the original entity-reference
  ordinal in the selected map. Their terrain checks cover 324 links and 34
  parents; batch-parent instances remain outside that result. Our SixNG
  `lodlinks.rs` instead infers some parent files by region, proximity, child
  counts and archive order. Its placement JSON retains the selector scalar but
  drops the parent-map array. Preserve that array and authored entity ordinals
  before replacing the heuristic for supported records. Parentage alone does
  not establish which collision bounds own a placement.
- Their [identity measurements](https://github.com/ubiquitarianism/leonida/blob/a73a57e1339be072baf5522351c8ec7f1482b56b/docs/world_names.md)
  distinguish a name-confirming 64-bit archetype key from a nonunique entity ID.
  Persistent simulation identity should include the source archive/version,
  map resource and authored instance ordinal, including nested placement paths.
- Our placement index contains 23,532 world maps / 1,670,435 entities. Leonida's
  newer [complete census](https://github.com/ubiquitarianism/leonida/blob/a73a57e1339be072baf5522351c8ec7f1482b56b/docs/world_census.md)
  reports 23,535 / 1,670,442. This is a count discrepancy, not yet an identified
  set difference. Their continuation-page handling is a lead to investigate.
  Our additional 961 interior resources and 6,296 group resources must not be
  counted as extra world cells: their transforms are local.
- Leonida's `world_build.py` implements shared geometry and tiered cell loading,
  but its viewer selects tiers using median distance bands. This is an
  approximation to authored entity links and cannot be reused as a contact
  refinement rule. Their `physicsDictionary` field gives a dependency to
  investigate; it does not supply mass, hinges, motor limits or validated friction.
- Their [navmesh measurements](https://github.com/ubiquitarianism/leonida/blob/a73a57e1339be072baf5522351c8ec7f1482b56b/docs/navmesh.md)
  distinguish 128 m static sectors, local dynamic meshes and a coarse global
  mesh. Ordinary adjacent edges use sentinels at tile borders and require
  runtime stitching; special links are a separate structure with incompletely
  understood traversal flags. These support route/prefetch work, not wheel or
  foot contact surfaces.
- The [BVH packs](https://github.com/ubiquitarianism/leonida/blob/a73a57e1339be072baf5522351c8ec7f1482b56b/docs/bvh.md)
  are dehydrated ray-tracing acceleration structures whose primitive references
  require drawable geometry. They are not an independently loadable collision
  world or MuJoCo contact acceleration data.
- VIctory's [water readback implementation](https://github.com/fxceless/victory-fork/blob/46bf5351707b1697c04e5d871c30973ebaa3e973/crates/victory-gpu/src/texback.rs)
  documents GPU-written ocean height/displacement maps read by CPU buoyancy.
  If water dynamics become a requirement, rendering and physical water queries
  need a shared field/time contract; a good-looking water shader is insufficient.

### Local spatial-index experiment

The independent audit is saved outside Git in
`experiments/review/world-index-audit/{audit.py,report.json,resource-bounds.sqlite}`
under the experiment root. It read the entire existing collision metadata file
(1,118,847,749 bytes; SHA-256
`5a3fd0ac68b07c8a6677f39b64fc04f16ef2e081c20b1de572aaf0777648d7d8`).
SQLite R-tree construction for 87,849 resource bounds took 8.30 s and produced
a 16,089,088-byte database. Five 24 m square queries around spawn and up to
200 m away returned 6–13 source candidates, with warm median lookup times of
0.009–0.011 ms. All seven audit queries were checked against an exact linear
AABB scan; no missing candidates or conservative extras occurred in this sample.
At the XY origin, the query returned 2,567 candidates in 0.34 ms, illustrating
why source-space classification and local density matter.

This measures metadata only: no GLB decode, triangle selection, model compile,
contact solve or cold disk access. The resource bounds are not yet joined to
placed instances. 2,521 resources have their entire XY box within the origin's
100 m square; bounds alone cannot prove whether each is local or world space.
The index is an audit artifact and is not connected to the live backend.

At the time of this initial metadata audit, `CollisionCatalog.select` scanned all
resident triangles and the sensor proxy remained fully resident. Enlarging that
NPZ to the entire map would therefore
retain map-size-dependent memory and selection work. Replace this with a global
instance/dependency index, bounded decoded/cooked caches and local triangle
indices. The new resource R-tree demonstrates that global metadata lookup is
cheap; it does not certify global physical coverage.

The implementation order is: preserve and validate authored placement/parent
identity; reconcile collider dependencies and analytic primitives; stream
validated source cells through bounded caches into the existing state-preserving
handoff; then run long routes and revisits with cold-cache delays. Prefetch must
cover travel during measured loading/compile latency plus braking distance and
the protected contact region. Retain loaded contact geometry and whole awake
interaction islands. Render/sensor detail and sleeping distant state have
independent residency policies. Similar local complexity can retain similar
performance across a larger world; dense scenes and additional active robots or
moving objects still increase cost.


### Renderer and visual-state validation (2026-11-26)

The SixNG experiment restores full authored rotation and scale through a
checksum-bound supplement to the old yaw-only map bake. Of 1,652,921 baked
placements, 904,184 matrices differ from the old approximation, 551,665 tilt by
more than one degree, and 82,936 have non-unit scale. Corrected centres drive
frustum and distance checks too. Generate the supplement with the renderer repo's
`tools/map-transforms/build.py`; it validates each source map/model/position row
before writing and the renderer rejects stale bake checksums.

Renderer fixes include finite degenerate-vector/HDR handling, exposure-correct
lighting/water history, and dropping malformed *triangles* rather than individual
indices. An audit of 65,255 cached GLBs / 438,231 primitives found no out-of-range
indices, so that loader defect is not evidence for the user's observed spikes.
Water/camera sweeps captured 511 baseline and 500 hardened frames without
reproducing the reported large white flashes/star shapes. These changes are
robustness fixes, not a claim that the original intermittent fault is reproduced.

A real map barrier was moved through the object bridge: original placement
suppression, RGB, shadow and depth changes were visually checked. This probe moved
its transform explicitly; it did not identify an authored hinge or demonstrate
physically correct barrier mass. Separate MuJoCo compiler/state tests cover hinge
and free-body persistence, including reopening at both old and moved locations.

The viewer's **Save glitch** button records the phone's displayed image, the
native RGBA frame, pose/simulation/streaming status and video transport metrics.
`G1_CAPTURE_DIR` selects persistent storage; capture reports are rate-limited and
bounded to 200 directories. The workstation uses the extra SSD. Native and phone
images can differ by transport latency; compare their timestamps before attributing
a discrepancy to NVENC/WebRTC rather than rendering.

Reference work inspected:

- [Leonida's authored placement and model checks](https://github.com/ubiquitarianism/leonida/blob/a73a57e/docs/world.md)
  confirm conjugated authored rotations and scale rather than yaw-only placement.
- [Leonida's SGD5 render-state tables](https://github.com/ubiquitarianism/leonida/blob/a73a57e/docs/sgd5_render_states.md)
  provide a route to recovering per-pass culling/depth/blend semantics; those tables
  are not yet wired into this reconstructed renderer.
- [Victory's 2026-11-26 graphics work](https://github.com/fxceless/victory-fork/commit/06702fe86b91bacbf4a0a27662ae443435bf732e)
  includes BC7 rotation and resource/dispatch fixes. SixNG's separate BC7 path
  already restricts channel-precision rotation to modes 4/5; importing that patch
  would not address the observed failure. Most of Victory's remaining changes
  concern its console-command/shader translation layer, which this renderer does
  not run.

Interior placement/name recovery is distinct from linking each interior to its
unnamed collision resource. The 2,112 heuristic interior/collider associations
remain withheld: the known archive-order/bbox method has only 91% hold-out
accuracy. Undecoded bound families remain open; no proxy-box substitution was
introduced to inflate coverage. The single-hinge work below recovers a subset of
fragment articulation; multi-panel motion, latches and tunable overrides remain open.

### Authored door admission and the contact blocker (2026-11-26)

`demo_discover_objects` creates a separate catalog from cached fragment metadata
version 3. It requires one rotational limit, a rigid bone frame, all visible skin
weights under that hinge, and complete supported collision children. GLB node
names/indices and hierarchy are checked; cyclic/incomplete hierarchies, fixed
visible frames, extra axes, sliding joints and tunable overrides are rejected.
Every robot-relevant collision child must match one decoded box in both bounds
and transform. Each placement needs positive uniform scale and a unique HD
map/model/position renderer binding. The source catalog is not overwritten.

Moving descendant masses are summed, with centres of mass and full inertia
tensors transformed into the model frame, combined with the parallel-axis
theorem, then diagonalized. MuJoCo retains the principal-axis orientation. Fixed
anchor mass is excluded. Intact glass/handles are welded to the moving panel;
this does not implement fracture, latches, drives or recovered hinge damping.

For the initial 341 cached `*door*` assets, 97 models and 5,014 of their 5,052
indexed placements passed structural admission. The 38 excluded placements lack
a unique renderer match. Among other cached models, 147 lack supported metadata
or have tunable overrides, 80 are not single hinges, 15 contain fixed/undecoded
collision and two have fixed visible parts or another assembly. This is not a
census of every door asset in the archive.

```bash
python -m dimos.experimental.gta_sim2.demo_discover_objects \
  --catalog /path/to/world-m20/catalog/catalog.json \
  --work /path/to/work \
  --output /path/to/new-door-catalog
```

**Structural admission is not world contact validation.** Full-world probes of
nearby doors found initial overlaps with floor/frame colliders: approximately
0.05 mm–30 mm in the first four cases. An 80 Nm torque barely moves those hinges.
Another door begins with roughly 51 mm penetration and is pushed open, which is
also a failure. Contact margins, surrounding geometry and the original game's
pair-filtering semantics still need reconciliation. Neither friction removal nor
arbitrarily disabling nearby collision is deployed as a solution.

The actual `levels.rpf@23ead3010/entity/2` door has a recovered moving mass of
28.179758 kg and authored limits of ±1.570796 rad. With surrounding contacts
disabled **only for a diagnostic**, torque drives it to the soft MuJoCo stop
(1.585191 rad peak under continued load). With world contacts enabled it moves
only 0.004971 rad after one second at 80 Nm. A stationary −0.9 rad pose survives
unload, SQLite close/reopen and recompilation with zero joint-angle error and
matching body position/orientation. That verifies real-asset state handling,
not collision-safe opening in the assembled world.

Native RGB-D captures of this real door confirm the panel and handle rotate
about the recovered pivot, its frame stays fixed, and its original static copy
is suppressed. Closed/open/revisit captures are in that same evidence directory.

The derived catalog is `world-m20-doors/catalog/catalog.json`; the browser keeps
using `world-m20/catalog/catalog.json`. Workstation evidence and reproducible QA
scripts are in `experiments/review/renderer-artifacts/door/`, with the full-world
contact probes in `logs/door-*.log`. No game geometry or metadata is committed.
