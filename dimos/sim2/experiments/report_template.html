DimOS sim2 · first principles, source code, measurements

Deltas save communication.
Finding them costs work.

A delta reuses information the receiver already has. Jeff's implementation first reads the exported state to find changes, then sends only changed groups. The question is whether the work avoided after detection exceeds the cost of detection and bookkeeping.

The central test: does saving encoding, transfer and receiver work pay for scanning, comparison and maintaining history?

Follow the argument: what is saved → what must be inspected → proof in the code → break-even equation → measured costs → implication for sim2. The existing experimental data is unchanged.

1 · A delta is a caching optimization

The receiver already knows most of the answer

Think of the exported world state as an ordered collection of records: object poses, robot-root velocities and joint values. A full sample contains all agreed records at a particular simulation time. A delta identifies changed records and supplies their new values. Jeff's receiver stores the accumulated state in a mirror.

Assume a known layout, separate sender/receiver copies and fixed-size records. Let N be the number of records, k the number changed, b the bytes per value and h the identity/metadata bytes per changed record. After the initial baseline, this simple indexed format sends:

Bfull=Nb Bdelta=k(b+h)

For a teaching example with 1,000 records of 64 bytes, ten changes and an 8-byte identity per update: a full sample sends 64,000 bytes; a delta sends 720 bytes, before message headers. Those other 990 values are already known. This is the communication saving.

The mirror still stores N records. It needs an initial baseline of the relevant state and identities. Over many updates, the saving is repeatedly avoiding unchanged transfers, not eliminating the initial copy or the state itself. If everything changes, this indexed format sends all values plus identities; a hybrid could instead fall back to a full sample.

These byte equations explain a format, not Jeff's exact wire layout. His updates have variable-sized groups and headers. The measurements below use his actual encoder.

2 · Communication and detection are different computations

To discover arbitrary changes by comparison, you must inspect the state

Suppose the publisher has the old and current arrays, but receives no list of changes. Can it correctly identify all changed entries while inspecting only k entries?

Proof by an unseen entry. Pick an entry the algorithm did not inspect. Consider two current states that agree everywhere it did inspect, but differ at that entry. The algorithm sees the same observations in both cases. It cannot reliably decide whether that entry should be omitted. To identify all arbitrary changes, it must inspect every entry in the worst case.

For fixed-size records, that is an Ω(N) lower bound: at least work proportional to N. Comparing a full current array with a previous array is normally O(N). Sending k changed records afterward does not undo that scan. An algorithm can conservatively send uninspected records, but then it loses the guarantee of sending only the changes.

A simulator that records changed objects while updating them can provide that list. A publisher may then do O(k) incremental work. But a solver can rewrite an array without changing its numerical values: “was written” and “changed enough to publish” are not the same condition.

The consumer also matters. If it turns the mirror back into a fresh complete N-record array every sample, that output construction is again Ω(N). Incremental messages provide the greatest processing benefit when the receiver can retain and use state incrementally.

4 · The condition for a win

Less output wins only when it saves more work than detection adds

For a simple linear, serial model after initial synchronization, define three time costs. a is the per-record cost through the full-sample path. c is the per-record cost of the delta path's N-sized work: extraction, comparison/history and any full-array receiver projection. d is its remaining cost per changed record: encoding, transfer and patch application.

Tfull=aN Tdelta=cN+dk
Delta is faster exactly when, within this model:
cN+dk<aN⟺kN<a−cd

Three consequences follow directly. If c ≥ a, this scanning delta path cannot win for any nonnegative k. If transfer is expensive, avoiding unchanged transfers can make the trade favorable. And making N larger at a fixed changed fraction does not itself guarantee a win: N cancels out.

Assumptions: N > 0, d > 0, fixed-size records, constant per-record costs, no stage overlap, and startup/repair/fixed message costs excluded. Jeff's comparison can short-circuit, so its effective cost can vary with activity. Cache effects, batching, variable groups and parallelism also require care. We have not fitted a, c and d; the measured ledger below does not assume they are constant.

Work addedDetection + history maintenance + extra patch bookkeeping
<
Work avoidedEncoding + transfer + replacement of unchanged receiver values

This is the precise interpretation of “less copying.” We must identify which allocations, serializations or receiver writes disappear, and compare their cost with the new work. The name WorldChange alone establishes none of those costs.

Does transfer change the answer?

Prediction: increasing the cost of transferring unchanged bytes can reverse the trade. We tested real local TCP through DimOS Zenoh with separate processes, then separately added a synthetic per-payload transfer delay.

$delivery_comparison

These comparisons use the experimental compact full sample and Jeff's delta path, so they compare complete implementations, not suppression alone. Achieved rate is actual publications per second; p95 is capture-to-usable-state latency's 95th percentile, summarized by the median across three trials.

On actual local transport, smaller packets did not offset Jeff's processing cost. Under the synthetic 10 Mbps delay, avoiding unchanged transfers did pay. The imposed delay is payload bytes divided by configured bytes/second, with OS timer overshoot; it is not a remote-network or Desktop benchmark.

Measured conclusion: this delta implementation demonstrably saves communication and downstream work. In the local workload, detection/build overhead outweighs that saving. Under the imposed slow-transfer condition, the communication saving is large enough to win.

6 · What follows for sim2

WorldState, ownership and synchronization are three separate choices

State contractWhich physical facts can a reader observe, in which frames and at what simulation time?
Storage and lifetimeCan it read an existing buffer? How long are those values valid, and who may change them?
SynchronizationDoes a separate copy receive complete samples, changed fields, or a combination?

A WorldState API does not itself force a copy. A borrowed view of an existing buffer can avoid copying, provided its validity and concurrent access are defined. Keeping an immutable historical snapshot after the producer changes its data is a different storage requirement.

Our current snapshot does make new arrays: the actual snapshot() implementation shows that. But replacing its public state contract with a delta protocol is not the only way to change its allocation behavior. We measured elapsed time and message bytes, not total memory-copy traffic.

A cached world also needs a correctness contract

If a receiver misses “cup position = 1.1” and the cup then stops, later deltas may never mention the cup. Those later messages are compatible with both an unchanged cup at 1.0 and a moved cup at 1.1. The missing information cannot be recovered from those messages alone.

Therefore, a delta mirror needs an initial baseline and a way to preserve or restore a valid continuation. Our injected late-join, missed-final-update and old-frame tests reproduce three recovery failures in the pinned mirror. Reliable delivery during an established connection does not itself initialize a late joiner.

Inspect the recovery results and relevant source$recovery_table

Full-sample tests assume a known layout. Old-frame rejection was not tested for those paths. Initial declarations are sent once; the mirror applies messages without a sequence-gap/order guard and ignores unknown identities. These were intentional faults, not observed random loss in the transport sweep.

The decision these experiments support: define readable state independently of its delivery format. Use compact full samples as the measured local baseline. Adopt incremental delivery where its avoided work exceeds detection/bookkeeping, and include the recovery cost in that decision.

To make publication truly proportional to changed data, the next investigation would need engine-provided change information or another justified way to avoid a full scan, plus consumers that preserve incremental state. That approach was not measured here. Vectorizing the current comparisons could instead reduce the scan's constant cost without changing its O(N) scaling.

The experiments do not establish the best possible delta implementation, full G1 policy/sensor behavior, GPU scaling or actual deployment bandwidth needs. Whole-world dense readers were tested; consumers reading only one robot or needing all derived link poses need their own cost accounting.
