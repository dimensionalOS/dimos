---
name: dimensional
description: Build and operate DimOS apps and blueprints with the dimos CLI and Python API, and inspect real sensor and memory results.
---

`bash` runs with DimOS's Python environment first on `PATH` and `DIMOS_ROOT` set to the DimOS checkout. DimOS reads `.env` from the working directory, so run DimOS commands and scripts from `$DIMOS_ROOT` unless the task needs another directory. When a command behaves differently than you expect, check its `--help` for the installed version.

- Apps: `dimos list`, `dimos show-config`, `dimos bake`, source edits, and external packages that expose blueprints through the `dimos.blueprints` entry point group. Run an external app by the qualified `distribution-name.blueprint-name` that `dimos list` shows. A bare name selects a built-in. Do not edit the built-in registry for an external app.
- Running systems: `dimos run BLUEPRINT --daemon`, then `dimos status`, `dimos log`, `dimos stop` and `dimos restart`. Only `dimos log` takes `--run ID`. The others act on the latest run, so when several systems run, target one through `list_runs()` and `stop_entry()` in `dimos.core.run_registry`. Never act on the latest run in place of the one you mean.
- Python: `Dimos.connect()` attaches a script to the stack serving the default `Coordinator` endpoint. `app.list_rpcs()` and `app.describe()` discover its module APIs. `docs/usage/python-api.md` in the checkout explains the API. `stop()` on that connection disconnects and leaves the system running.
- Skills: a module's `@skill` methods are RPCs, and a script calls them like any RPC. `dimos mcp call NAME --arg KEY=VALUE` calls one through McpServer instead, which refuses a skill while another skill holds a capability it needs, such as movement.
- The rest of the CLI works from `bash` too: `mcp`, `agent-send`, `topic`, `map`, `rerun-bridge`, `mem`, `data`, `imitation`, `cache`, `evals`, `hardware`, `go2tool`, `cameracalibrate`, `apriltag`, `login`, `logout` and `whoami`. `shell`, `spy`, `lcmspy`, `agentspy`, `humancli` and `top` need an interactive terminal, so do not run them through `bash`.
- Dimensional cloud login (`dimos login`) and model-provider login are separate. Never ask for credentials in chat or in tool arguments. The user logs in to a model provider with `/login` in the terminal.

For the running system (module APIs, streams, agent modules and cron jobs), read the dimos-runtime skill.

For a recording, search the dumped caption JSONL with `rg` if it is on PATH, otherwise `grep -E` (`captions.jsonl`, or `captions/YYYY-MM-DD.jsonl` listed in `captions/manifest.jsonl`). Each line is one second with relative `t`. When `tracks.jsonl` (or `tracks/YYYY-MM-DD.jsonl`) is present, grep track `id`/`name` the same way — the same id across nearby seconds is the same object (`dimos mem track PATH --out DIR` writes those files). Index first, in several rounds: grep the whole recording, then again with synonyms and the question's time constraint. Collect candidate t values from captions and tracks before looking at pixels. Later hits are other candidates, not extra evidence for the first. A gap of several seconds is a new episode. If choices are timestamps, inspect those t values. Unique-count: distinct track ids; inspect at most one frame per id. Then `memory inspect(t)` only when the index cannot answer (color, clothing, motion, barriers, door numbers, open/closed, spatial referents). `t` may be one second or a list of up to four; several times return one labeled strip (2–3) or 2x2 grid (4) for motion/direction compare. inspect returns the image only, not the 1 Hz caption. Pass `ask` with several questions covering both competing answers: some direct, some that would refute the pick or corroborate it indirectly. Captions are a coarse 1 Hz index (`dimos mem caption PATH --jsonl FILE` writes the stream; `dimos mem dump-captions PATH --out DIR` writes the files). Inspect the shortlisted t in that window, a few frames, not a dense sweep and not weakly related earlier/later segments. If the question lists no choices, answer in a short phrase and do not invent options. For multiple choice, pick the option that matches the image, not the first grep line. Before the final answer, pause: restate the question and competing choices, name the index hits and any inspected t values that support the pick, and check unique vs repeated views, earlier co-occurrence vs a later frame, and duration endpoints. If the last thought named a different choice, inspect one more confirming t in the same window or keep that choice. Do not open the sqlite store from bash to answer a question about the recording. For custom analysis beyond inspect, use stream operations: evaluate a query once with `materialize()`, then derive scores, selected peaks, images and comparisons from that one result. Keep timestamps, observation IDs and coordinate frames in exports. `Space.to_svg()` and `Plot.to_svg()` draw spatial and timeline views.

Files that a `bash` command creates or changes in its working directory, one folder below it or the temp directory, and existing files whose paths appear in its output, are shown to you and to the user when they are one of these:

- a PNG, JPEG, GIF, WebP, SVG, TIFF or AVIF image;
- point-cloud JSON, `{"points": [[x, y, z]], "colors"?: [[r, g, b]], "frame"?, "timestamp"?, "selectedIndices"?}`, with colors from 0 to 255;
- a frame index, `{"type": "points" | "image", "timeOrigin"?, "source"?, "frames": [{"path", "timestamp", "sha256"?}]}`, with each path relative to the index and timestamps that strictly increase.

To show a file saved anywhere else, print its path.

A frame index plays as a loop for the user. You receive a contact sheet with each frame's timestamp, and you read any single frame with `read`. Do not claim to have inspected every frame from the contact sheet alone. For a recorded interval, materialize it once in DimOS, export its frames, and write the index with the recording's origin as `timeOrigin`.

For validation, start with the `unitree-go2` blueprint in replay mode: `dimos --replay run unitree-go2 --daemon`. Do not infer a physical robot's address from a default IP.
