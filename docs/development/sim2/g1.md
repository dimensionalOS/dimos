# G1 proof: articulated observations and separate control

This example uses the existing GR00T balance/walk task to drive a G1 beside a desk
and loose box. It tests the generic sim2 contracts with 29 driven joints and
mounted camera/lidar. It is not a replacement for the production G1 connection
or a new ControlCoordinator.

```bash
uv sync --all-groups --extra cpu --inexact
uv pip install 'mujoco>=3.3.4'
source .venv/bin/activate
dimos run unitree-g1-sim2 --daemon
dimos status
dimos shell
```

Existing G1 meshes, GR00T ONNX policies and desk meshes resolve through `LfsPath`;
the desk archive is a Git LFS pointer, not mesh data in the code diff.

In the shell:

```python
from dimos.msgs.geometry_msgs.Twist import Twist
app.G1PolicyDemo.move(Twist(linear=(0.2, 0, 0)), duration=2.0)
app.G1PolicyDemo.arm_joint("g1/left_elbow_joint", 1.4)
app.SimModule.reset()
app.SimModule.timing()
app.SimSensorModule.statistics()
```

Open **Controller** in DimOS Desktop. Set fixed frame to `world` and follow frame
to `g1/pelvis`. The blueprint publishes ordinary image/depth/lidar/TF messages.
Controller's standard `/cmd_vel` output is connected to the example policy host;
its arm-planner UI is not wired. Desk and box are visible in camera and lidar;
the Controller's default single-URDF request loads the G1 model. This change does
not add a multi-model Desktop scene loader. Stop with `dimos stop`.

The current local Desktop launcher at port 1024 discovers this blueprint but has
no Controller installed; the previous Controller service at port 5555 is stopped.
Visual Controller acceptance was therefore not completed in this verification.
The worker test verifies actual images, depth and lidar independently of that UI.

## Trace the code

1. [Blueprint](/dimos/robot/unitree/g1/blueprints/basic/unitree_g1_sim2.py):
   `G1_MODEL` chooses the existing URDF and attaches IMU, optical camera and lidar.
   `MODELS` is passed only to `UrdfManager`. `WORLD` refers to instance IDs and
   adds placement, drives and sensor profiles.
2. `UrdfManager.resolved_models()` returns the resolved descriptions before start.
   `SimModule` binds them into `WORLD`; the sensor module obtains that exact world
   through `describe_world()`. There is no second G1 model maintained for sensing.
3. Physics publishes a full `Observations` batch: 44 named body/frame poses in
   this scene. Camera/lidar use a query model with `nq=nv=nu=0`; moving limbs are
   placed from their body observations, without transmitting joint coordinates.
4. Separately, `robot_feedback: ControlValues` carries coherent measured joint
   state and native mounted IMU. [G1PolicyDemo](/dimos/robot/unitree/g1/demo_sim2_control.py)
   feeds that into existing `G1GrootWBCTask` and publishes generated `Actions`
   containing `JointCommand`. The existing task now permits its already-supported
   IMU-in-state input without requiring a hardware adapter.
5. Physics runs at 500 Hz; feedback/policy at 50 Hz. At each policy boundary,
   physics waits for a command answering that tick. Late inference slows sim time
   rather than skipping physics or replaying stale policy inputs. Duplicate
   feedback retransmits the previous action without advancing policy history.
6. Camera is scheduled at 15 Hz of simulation time; lidar at 10 Hz. Reset clears
   policy history, commands and scan history. A new camera reader can render from
   one complete batch after loading the description.

## Reproduce the acceptance check

```bash
pytest dimos/robot/unitree/g1/test_sim2_observations.py -m native_e2e
```

The test deploys actual workers, stands for two simulated seconds, walks forward
for three seconds, moves the left elbow, checks upright height/displacement,
attaches a new independent renderer, and resets while rejecting old observations.
The generic core tests cover malformed/missing/duplicate poses, scan history gaps,
forces, command expiry and typed message round-trips.

Local macOS verification (2026-11-02): native G1 test passed; ordinary CLI run
remained upright after 286 simulated seconds, with no rejected commands or sensor
errors. A subsequent 10.19-second wall-time sample advanced 9.66 simulated seconds:
14.12 camera frames/wall second, 14.91 frames/simulated second, approximately 0.95
real-time factor. This is a smoke measurement on this machine, not a scaling or
real-time guarantee. One startup scan-history gap was recorded, with no dropped
observations. Reset timing and other physics backends are not benchmarked here.
