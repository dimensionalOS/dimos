# Consume manipulation plans on dispatch

Manipulation execution consumes the pending plan on every dispatch attempt, whether the control coordinator accepts or rejects the trajectory. Reusing a cached plan after an execution attempt risks replaying motion or retrying a plan whose start state is stale, so another attempt requires planning again. Planning may return a complete plan snapshot for inspection, but execution accepts no plan argument and can dispatch only the module's authoritative pending plan. An immediate `move_*` operation invalidates any existing pending plan before it begins planning and never restores the old plan if the move fails. Execution blocks for physical completion by default. Explicit non-blocking execution still waits for the control coordinator's acceptance or rejection and skips only the subsequent completion wait. A wait timeout never cancels active motion; cancellation remains a separate explicit operation.
