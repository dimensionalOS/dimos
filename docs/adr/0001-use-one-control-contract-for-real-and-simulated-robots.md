# Use one control contract for real and simulated robots

Control coordinator subclasses declare typed command and observation ports, and real and simulated connection modules implement the complementary contract. Blueprints select the connection module without changing coordinator behavior. Each coordinator subclass constructs a generic port-backed adapter from its own typed ports; the adapter preserves the synchronous `WholeBodyAdapter` API but owns neither transports nor topic names. This avoids simulation-specific coordinator behavior and private IPC such as shared memory. A connection module atomically holds the latest complete motor command and applies it on every control or physics step until a newer command arrives. It publishes motor state at its native step rate while consumers retain only the latest complete observation, so feedback neither accumulates nor backpressures the connection.
